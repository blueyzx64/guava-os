# Guava OS: code map

> **Summary (read this and you can stop):**
> 1. `extension.js` is the composition root: it puts back any GNOME setting a crashed session
>    still held (`core/originals.js`), builds the core services and starts the feature registry
>    with one `ctx`.
> 2. `features.js` lists every feature: an id, its on/off key (or `when`), a lazy `load()`, and
>    `conflictsWith` / `needs` for shared resources. `lib/featureRegistry.js` starts and stops
>    them edge-triggered, in list order, and only loads the modules of features that are on.
> 3. `core/` holds the shared desktop picture every feature reads (windows, apps, focus,
>    workspaces, monitors), edge ownership and the work area, motion rules, a typed event hub,
>    the saved originals of GNOME keys, and the coordinators (panel slots, window flags,
>    notification routing, MPRIS). Pure `*Model.js` files, thin Shell adapters.
> 4. `features/<name>/` holds one feature: `index.js` (Shell adapter, the class the registry
>    starts), `model.js` (pure logic) where there is logic, `prefs.js` (its preference groups),
>    `style.css` (its Shell CSS). Features never import each other.
> 5. `stylesheet.css` is generated (`make css`) from `styles/base.css` and every
>    `features/*/style.css`, and committed. The preferences are `prefs.js` + `prefs/`.
>
> How to write a feature: `docs/architecture/conventions.md`. Feature pages: `docs/features/README.md`.

Target: GNOME Shell 50 (Fedora 44, Wayland). What 51 changes lives only in `lib/compat.js`.

## 1. Tree

```
extension.js          composition root (enable/disable)
features.js           the feature list (start order; conflicts and needs)
metadata.json  schemas/  po/  icons/
stylesheet.css        GENERATED by tools/build-css.sh, committed
styles/base.css       Shell CSS of lib/ services (glass fills, modal frames)
core/                 shared services: pure models + Shell adapters
lib/                  infrastructure without feature knowledge
features/<name>/      one folder per feature
prefs.js  prefs/      the preferences window (sidebar shell, widgets, pages)
tests/                gjs -m unit tests (tests/run.sh)
tools/                build-css.sh, check-pack.sh, smoke/
docs/                 architecture and feature pages
```

Packed into the zip (`Makefile` EXTRA and `.github/workflows/pack-release.yml`): `icons lib core
features prefs features.js`, plus what `gnome-extensions pack` takes by default (`extension.js
prefs.js metadata.json stylesheet.css schemas/ po/`). `make pack-check` verifies it.

## 2. Startup and the ctx

`extension.js enable()`:
1. `Glass.configure(settings)`, `IconStyle.configure(settings)`.
2. `restoreStale()` (every value left in `saved-originals`).
3. Core services: `EventHub`, `DesktopService`, `LayoutService`, `Motion` (started).
4. `FeatureRegistry.start(ctx)`; a settings `changed` handler refreshes it (except the keys
   Guava writes at run time: `clipboard-recording`, `saved-originals`, ...).

`disable()` mirrors it: registry stop (reverse order), services stopped, hub cleared.

`ctx` (the same object for every feature):

| Field | What |
|---|---|
| `extension`, `settings`, `gettext` | the Extension, Guava's `Gio.Settings`, its gettext |
| `features.instance(id)` | the running instance of another feature, or null (look up at use time) |
| `events` | `core/events.js` EventHub |
| `desktop` | `core/desktop.js` DesktopService (`acquire(cleanup)` starts tracking) |
| `layout` | `core/layout.js` LayoutService (`acquire(cleanup)`, `claim()`, `workArea()`) |
| `motion` | `core/motion.js` Motion (`ease`, `spring`, `env`) |
| `appMenus` | `core/appMenus/service.js` AppMenuService (menus of the focused app) |
| `osd` | `core/osd.js` OsdRouter (`setSink(cleanup, 'notch'\|'pill', fn)`) |
| `originals` | `core/originals.js` OriginalsStore (give it to a `SettingOwner`) |
| `timers` | `core/timers.js` TimerService (`startTimer({seconds, label})`, `pause/resume/cancel(id)`, `list()`, `remaining(t)`) |

## 3. core/

| File | Role | Main API |
|---|---|---|
| `events.js` | typed signal hub; events declared once in `EVENTS` | `on(name, fn, owner?)`, `once`, `emit(name, payload)`, `listenerCount`, `clear` |
| `desktopModel.js` | pure desktop picture | `upsertWindow(id, fields)`, `removeWindow`, `window(id)`, `windows(filter)`, `apps(filter)`, `setFocus`, `focusedWindow`, `focusedApp`, `setWorkspaces`, `setMonitors` (WindowInfo has `above` and `parent`, the transient-for id); `isHelperWindowInfo`, `isUserFacing`, `appIdCandidates` (web-app ids for window-backed apps) |
| `desktop.js` | feeds the model from Mutter; one tracker, ref-counted | `acquire(owner)`, `model`, `metaWindow(id)`, `tracking`, `stop()` |
| `layoutModel.js` | edge claims -> rects and work area | `claim(spec)`, `update(id, fields)`, `release(id)`, `compute(index, monitorRect, {base, primary, strutsApplied})` |
| `layout.js` | claims the menu bar itself; Mutter's work area as the base; an `actor` claim is chrome (hidden over full screen), with struts while its reserve is `strut` (`update({reserve})` switches live) | `acquire(owner)`, `claim(owner, spec)` -> `{rect, update, release}`, `rect(id, monitor)`, `workArea(monitor)` |
| `motionModel.js` | durations, curves, springs; animations-off and reduced-motion rules | `DURATIONS`, `CURVES`, `SPRINGS`, `resolve(request, env)`, `splitProps`, `springAt`, `springDuration`, `springKeyframes` |
| `motion.js` | applies them to actors; cancellable | `start/stop`, `env`, `duration(req)`, `ease(actor, props, req, owner)`, `spring(actor, prop, to, req, owner)`, `tween(actor, req, onFrame(p), owner)` (a 0..1 progress for meshes and computed layouts) |
| `desktopActions.js` (+`Model`) | one desktop action (Mission Control, App Exposé, Desktop, Notification Center, Launchpad, lock, display sleep) for hot corners, gestures and the switcher; asks the owner by event or `ctx.features`, stock fallback when nobody listens | `new DesktopActions(ctx)`, `run(action, {source, appId?})`, `allowed(action)`; `DESKTOP_ACTIONS`, `normalizeAction` |
| `originals.js` | the user's value of GNOME keys Guava owns (pure; the Shell side is a Gio.Settings) | `OriginalsStore`, `SettingOwner(store, settings, key, {type, transform/value, onOriginalChanged})` with `sync/reapply/release/original`, `restoreStale(store, openSettings)`; `ListMembersOwner(store, settings, key, members)` takes only some members out of a string list (Dash to Dock from `enabled-extensions`) and adds back just those |
| `tileActions.js` | tiling vocabulary: zones, arrangements, `parseAction` (payload of `window-tile-requested`) | `ZONES`, `ARRANGEMENTS`, `parseAction` |
| `panelLayout.js` (+`Model`) | who sits where in the top bar; hides stock items | `PanelLayout.claim(cleanup, {id, actor, box, anchor})`, `PanelLayout.hide(cleanup, role)` |
| `windowState.js` | why a window is not in its normal place (`staged`, ...) | `WindowState.set/has/list/watch`, `interceptMinimize`, `setStageActive` |
| `notificationRouter.js` | banners to the notch or stock, shared `{count, dnd}`, banner filters (Focus), the history | `setBannerSink`, `setBannerFilter`, `pinBanners`, `connect`, `watchHistory`, `sources`, `appIdOf`, `state`, `setDnd` |
| `mprisWatcher.js` | one MPRIS source for the extension | `MprisWatcher.acquire(cleanup, gettext)` |
| `widgets/` | the one widget model for the desktop layer, Notification Center and notch: pure `model.js` (sizes, grid, snapping, layout JSON, `ProviderPool`, `WidgetRegistry`), `data.js` (pure data shaping), `view.js` (the glass card), `providers/` (time, calendar, weather, batteries, media, system; lazy and shared), `kinds/` (the built-in widgets) | `Widgets.acquire(cleanup, gettext)` -> `host.registry`, `host.createView(kind, {size, config, scale}, owner)` -> `view.actor`, `setActive(bool)`, `activate()`, `menuItems()` |
| `osdModel.js` / `osd.js` | the one interception of the Shell OSD (`_showOsdWindow`): classifies volume / brightness / keyboard backlight and routes each change to ONE sink from `osd-location` (notch while it runs, else the menu-bar pill; 'system' = stock); other OSDs and other monitors stay stock | `classifyOsd`, `route`; `OsdRouter.start(cleanup)`, `setSink(owner, name, fn)` |
| `appMenus/` | the focused app's menus (ctx.appMenus): pure `model.js` (generic menus, well-known GTK actions, Help search, ⌘ shortcut labels), `gtkActions.js` (org.gtk.Actions provider), `commands.js` (generic commands), `service.js` (providers, cache, activation); menu bar providers: pure `nativeModel.js` (GMenu store, DBusMenu layout, AT-SPI nodes, `applyMenubar`), `gtkMenus.js` (org.gtk.Menus exported menu bar), `dbusMenu.js` (com.canonical.AppMenu.Registrar + com.canonical.dbusmenu, Xwayland apps by X11 id), `atspi.js` (experimental: async a11y-bus reads, libadwaita primary menu off-sight) | `acquire(owner)`, `targetFor(win)`, `peek/results(target)`, `build(target, results, opts)`, `activate(target, command)`, `registerProvider(owner, provider)`, `onChanged(owner, fn)` |
| `timersModel.js` / `timers.js` | Guava's own countdown timers (wall clock, stored in `timers-state`, survive the lock screen); one alarm timeout, no tick | `ctx.timers.startTimer({seconds, label})` -> id, `pause`, `resume`, `cancel`, `list`, `remaining`; events `timers-changed`, `timer-finished` |

Events (`EVENTS` in `core/events.js`): `window-added`, `window-changed`, `window-removed`,
`window-focused`, `app-focused`, `workspaces-changed`, `monitors-changed`, `work-area-changed`,
`motion-changed`, `feature-changed`, `minimize-requested`, `notification-center-requested`, `focus-changed`
(the clock), `app-hide-requested` and `window-tile-requested` (app-menu commands for the
window manager; the menu bar runs a fallback when nobody listens), `launchpad-requested` (dock tile,
pinch, hot corner), `split-view-changed` (Split View), `recording-started` /
`recording-stopped` (screenshots; for the notch's recording live activity), `timers-changed`,
`timer-finished` (core/timers).

## 6. Preferences

`prefs.js` builds the window from `prefs/pages/index.js` `SECTIONS`; `prefs/window.js` is the
sidebar (sections, search across every row, narrow-window collapse); `prefs/widgets.js` the
shared rows; each page module composes `features/<name>/prefs.js` `buildPrefs()` groups.
Order: General, Login Items (`loginItems.js`, model `lib/loginItemsModel.js`) | Menu Bar, Dock, Windows, Stage Manager | Notch, Spotlight, Control Center,
Clipboard | Appearance | About.

## 7. Settings

`schemas/org.gnome.shell.extensions.guava-os.gschema.xml` groups keys by feature. A key of a dropped
feature is removed with it. Internal keys: `saved-originals`, `clipboard-recording`.

## 8. Tests and checks

`make check` = eslint (pure modules may not import `gi://`/`resource://`; prefs may not import
Shell modules; Shell code may not import GTK) + strict schema compile + `make css-check` +
`tests/run.sh` (every `tests/*.test.js` under `gjs -m`). `make pack-check` packs and checks the
zip. Real Shell: `GUAVA_SRC=$PWD tools/harness/run-f44.sh 20` (see `tools/harness/README.md`).
